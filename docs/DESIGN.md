# Design system

The companion combines readable editorial layouts with the tropical, cinematic colors of Vice City. Search and map access remain prominent; imagery supports content without filling every page.

Shared tokens in src/app/globals.css: Dark Navy #15152D, Deep Violet #51258C, Hot Pink #FF3D9A, Neon Purple #8A3FFC, Sunset Orange #FF7849, Peach #FF9B8E, and Miami Cyan #39D5D8. Navy and violet anchor backgrounds. Pink/orange gradients use dark text on primary buttons; cyan is reserved for focus and completed discoveries. Body copy uses light neutral lavender.

Space Grotesk and DM Sans are self-hosted through `next/font` and exposed as `--font-display` and `--font-body`, with system fallbacks. They were previously pulled in by an `@import` at the top of globals.css, which cost an extra request chain before any text could paint and sent every visitor's IP to a third party.

Type has a 10px floor. Micro-labels that were set at 8.3-9.6px are now 10-11px and carry their small-caps character through letter-spacing rather than size.

Surfaces share one depth recipe: a 1px inset top highlight and a wide, low-opacity drop shadow. Cards lift 2px toward the pointer. Depth comes from those two cues rather than from additional colour.

Official Rockstar screenshots appear in the homepage hero, three guide covers, and banners on missions, characters, locations, and guides listings. Attribution is visible, with provenance in MEDIA.md. Images are decorative context, not evidence for fictional database entries. Generated concept artwork is no longer referenced by the UI.

The map remains an explicitly fictional 1600x1000 SVG schematic, generated by scripts/map.mjs. Its colors now match the site. The controller reconciles keyed marker and cluster layers, cancels outdated requests, buffers viewport queries, and debounces movement. Selection updates native URL history without server navigation. Focus pans only enough to expose a marker outside the detail panel and preserves zoom. Desktop details float over the canvas; mobile uses a bottom sheet. Resize preserves center and zoom, with a responsive minimum zoom. Reduced-motion preferences disable map animation and inertia.

Marker transforms remain exclusively owned by Leaflet; only inner glyph colors and shadows transition. Cluster badges are drawn on an inner span rather than the icon root, so they can shrink on small canvases without disturbing the anchor box Leaflet positions; the count is written into that span, because writing it to the root replaced the span with a bare text node. Category icons, completion checks, keyboard activation, focus indicators, a text marker directory, and retry controls support navigation beyond color alone.

The map stage carries a soft horizon gradient and the Leaflet canvas above it is transparent, so the letterboxing on tall viewports reads as water around a landmass rather than as unfilled page. Zoom controls, the compass, the disclaimer and the hint share one translucent overlay treatment. Map height is derived from `--header-h` and `--mobile-nav-h` instead of repeated literals, with a `vh` fallback ahead of `dvh` so a browser without `dvh` cannot collapse the canvas.

Motion uses one scale, declared in transitions.css: `--dur-fast` 150ms for state changes, `--dur-base` 260ms for reveals, `--dur-slow` 640ms for image drift, with `--ease-out` for arrivals, `--ease-exit` for departures and a shallow `--ease-soft` overshoot. Durations and curves were previously chosen per component, so each surface answered a hover at a different speed.

Checkboxes and selects are drawn by the design system. `accent-color` left the unchecked checkbox to the platform, which rendered as a pale grey-green square against the navy.

Layout breakpoints remain 600, 768, 900, 1024, 1150, and 1700 pixels.

The editorial workspace inherits these tokens through globals.css. Its own sheet adds the shared surface depth, hover feedback on content rows, an accent rail on the active nav item, and a scroll-safe nav strip on narrow screens, so moving between the public site and the CMS does not feel like two products.

Browser verification has now been run against a production build in headless Chromium: 15 routes at 390, 600, 768, 834, 1024, 1280, 1440 and 1920 px with no horizontal overflow, no console errors and no failed requests; plus 2560 ultrawide and a 720px narrow window. The map was exercised for marker selection, filters, deep links, rapid wheel zoom, a repeated-resize storm, reset, an unknown marker id, a blocked marker API, a blocked map image and throttled 3G. Keyboard checks used real key events: every stop has a visible focus ring, the palette traps focus and returns it to the control that opened it, and Escape closes the palette and the More menu.

Motion was verified by sampling computed style mid-effect rather than by reading the CSS: card hover travels 0 to -2px on a decelerating curve over ~300ms, the category rail scales 0 to 1 over ~280ms, the palette fades in over ~180ms, and a route change runs real `::view-transition-old/new` animations (`hub-fade-out`/`hub-sink` at 140ms out, `hub-fade-in`/`hub-rise` at 280/420ms in) with the outgoing page held under a pending bar rather than replaced by a skeleton.

User journeys were driven end to end: mark-complete and favourite persist across a reload and appear on the account page, the collectible checklist toggles, cheat platform tabs switch, listing sort and search submit and produce a real empty state, registration issues a recovery code, and a community submission returns a reference id.

Still unverified: Firefox and Safari rendering, and real touch input on hardware. Safari prefixes (`-webkit-backdrop-filter`) and non-`dvh` fallbacks are in place but have not been exercised in those engines. Automated interaction-controller checks use a mocked Leaflet adapter and do not substitute for browser rendering.
